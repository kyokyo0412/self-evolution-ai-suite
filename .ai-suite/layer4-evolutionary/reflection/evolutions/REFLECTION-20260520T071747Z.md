## Task Summary

The previous task enhanced the reflection protocol: it added a 5-category analysis framework, a 3-question generality gate, and a structured evolution report step. During implementation (TDD phases), `test-refactor-eut.sh` contained a hardcoded validator check count (`36`) that broke when the `remote-suite.md` skill was added, requiring a manual fix mid-task. This was the same class of breakage fixed in the prior reflection cycle (`run-acceptance-tests.sh` count `13`). The pattern repeated because `tdd-team.md` contained no constraint forbidding hardcoded corpus sizes.

## Improvement Target

- **File:** `.ai-suite/layer3-registry/core/tdd-team.md`
- **Tier:** core

## Root Cause

- **Category:** Instruction Completeness
- **Severity:** High
- **Description:** The `tdd-team.md` SDET guidance had no rule about dynamically computing corpus-size counts in test assertions. When SDET writes tests that assert `[[ "$count" -eq 36 ]]`, any future skill addition causes an unrelated test failure, triggering a stop-and-fix interrupt mid-task. The same fix was applied twice in consecutive tasks, confirming this is a structural gap in the skill, not a one-off mistake.

## Change Description

Added a new bullet to the **Negative Constraints** section of `tdd-team.md`:

> [X] **Do not hardcode corpus sizes in test assertions.** Any assertion on a count that grows with the codebase (number of skills, rules, check passes, files in a directory) MUST be computed dynamically at test runtime -- never as a literal integer.

Includes a Good/Bad code example and an explicit rationale tying it to the observed failure pattern.

- Q1 (all agents): YES -- TDD testing principles apply to every AI agent
- Q2 (agent-specific): NO
- Q3 (domain-specific): NO
- **Tier chosen:** core
- **Justification:** The "never hardcode corpus sizes" constraint is a universal TDD best practice independent of agent type or software domain.
