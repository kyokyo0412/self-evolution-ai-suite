machine and on remote host sunlinux. The execution environment was a sandboxed
runtime (Codex CLI, workspace-write sandbox, approval mode never): writes to
~/.codex and outbound SSH were denied mid-install with "Operation not permitted".
The skill gave no guidance for this case, so the agent had to improvise a
read-only verification + handoff path.

## Root Cause
- **Category:** Instruction Completeness
- **Severity:** High
- **Description:** The skill only prescribed "run the command and stream
  output". In a sandboxed execution environment the command fails
  non-idempotently (partial mirror) and the agent has no defined fallback,
  risking repeated failed retries or an unverified handoff. The failure
  signatures (cp/mkdir "Operation not permitted", ssh connect denied,
  harness "Rejected(...)") are deterministic and detectable, so a
  stop-verify-handoff procedure is fully prescribable.

## Change Description
Added "### 4. Restricted Execution Environment (Sandbox) Fallback" to
local-suite.md listing the three sandbox failure signatures and a 5-step
fallback: (1) stop mutating, (2) read-only verify of the existing deployment
with byte-compare vs repo source, (3) confirm no damage (sentinel block and
foreign entries such as ~/.codex/skills/.system intact), (4) hand the user
exact commands for an unsandboxed terminal, (5) report the delta
(installed vs stale/missing). Also added step 5 to the Step-by-Step Execution
list referencing the new section so it is discoverable.
