## Task Summary
The user requested to enable the ai-suite for the local machine and two remote servers globally for Cursor. The AI agent completed the task but completely ignored the `interactive-workflow` rule, which mandates asking the user if they want an interactive workflow at the very beginning of the task.

## Improvement Target
- **File:** `.ai-suite/layer1-abstraction/agents/cursor/rules/interactive-workflow.md`
- **Tier:** agents/cursor

## Root Cause
- **Category:** Instruction Completeness
- **Severity:** High
- **Description:** The `interactive-workflow.md` rule instructed the AI to use the `AskQuestion` tool at the beginning of any task, but lacked a strict negative constraint (hard block) to enforce this behavior before taking action. Without a hard barrier, the AI agent optimized for task completion and jumped straight into shell commands, bypassing the intended interactive workflow prompt entirely.

## Change Description
Added a strict negative constraint (HARD BLOCK) to the `interactive-workflow.md` rule:
`** HARD BLOCK: You MUST NOT execute any state-changing tools (e.g., Shell, Write, StrReplace) or begin the main task execution until you have FIRST called the AskQuestion tool to ask if the user wants an interactive workflow and received their answer.**`
This explicitly blocks the AI from using state-changing tools until it has fulfilled the initial prompt requirement.

## Generality Gate Result
- Q1 (all agents): NO
- Q2 (agent-specific): NO
- Q3 (domain-specific): YES (Cursor-specific)
- **Tier chosen:** agents/cursor
- **Justification:** The `AskQuestion` tool and the interactive workflow rule are strictly specific to the Cursor Agent.

- Added a new ` HARD BLOCK` constraint prohibiting the execution of state-changing tools or beginning the main task execution before calling the `AskQuestion` tool at the start of the task.
