## Task Summary
The human requested to fix unreadable characters in the `README.md` file. In the previous task, the AI had used the shell command `cat << 'EOF' > README.md` to generate the file, which corrupted UTF-8 characters (like tree structures and arrows) due to shell encoding issues, requiring a multi-turn recovery.

## Improvement Target
- **File:** `.ai-suite/layer3-registry/safety/production-safety.md`
- **Tier:** meta

## Root Cause
- **Category:** Tool-Use Efficiency
- **Severity:** High
- **Description:** The AI used shell redirection (`cat << EOF > file`) to create a large file containing UTF-8 characters instead of using the native agent file-writing tool (`Write` or `StrReplace`). This caused character encoding corruption and required the user to ask for a manual fix.

## Change Description
Added a new constraint to the `Refuse-by-Default Patterns -> Shell` section in `.ai-suite/layer3-registry/safety/production-safety.md`. The rule explicitly forbids using `cat << EOF > file` or `echo "..." > file` for multi-line or UTF-8 file creation, mandating the use of the native agent file-writing tool to prevent encoding corruption and escaping bugs.
