## Task Summary
The human requested to fix the installation paths for the OpenCode adapter, changing the path from `~/.opencode` and `.opencode.md` to `~/.config/opencode` and `.opencode/`. While the AI manually addressed the path updates successfully across six separate files, the agent uninstall mechanism failed to clean up the legacy `.opencode.md` files locally.

## Improvement Target
- **File:** `.ai-suite/layer4-evolutionary/validation/meta-install-contracts.md` (and `.ai-suite/layer1-abstraction/agents/opencode/adapter.sh`)
- **Tier:** meta (and agents/opencode)

## Root Cause
- **Category:** Instruction Completeness
- **Severity:** High
- **Description:** When adapter paths evolve or change (like OpenCode moving to `.opencode/`), the uninstall functions are frequently updated to point to the new paths but lack explicit logic to detect and remove the stale legacy paths. This leaves stale configuration blocks inside deprecated files or folders (e.g. `.opencode.md`) that can corrupt user setups and IDE extensions.

## Change Description
Updated `.ai-suite/layer4-evolutionary/validation/meta-install-contracts.md` to explicitly mandate a new "Backward Compatibility (Legacy Cleanup)" constraint. This dictates that whenever an agent's standard configuration path evolves, all associated `agent_uninstall_*` scripts MUST gracefully identify and delete the old legacy paths. Added this cleanup rule to `.ai-suite/layer1-abstraction/agents/opencode/adapter.sh` for the legacy `.opencode.md` block and wrote `.ai-suite/layer4-evolutionary/validation/test-legacy-cleanup.sh` to prove that it executes effectively.
